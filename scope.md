# Metronome MVP scope

## Decision

Build the first release as a responsive client-side web application with installable and offline PWA support.

One public HTTPS link must work across current Windows, macOS, Linux, ChromeOS, Android, iPhone, and iPad devices without requiring an account, app store, plug-in, or native installation. Installation is optional for the user: the product remains a normal website everywhere.

All capabilities that are not required for this first public release are tracked separately in [future.md](future.md).

## Browser support policy

Support modern, maintained browsers rather than historical browser releases.

- Use Vite's current `baseline-widely-available` production target.
- Test the current stable Chrome, Edge, Firefox, and Safari releases.
- Test current Chrome on a maintained Android release and current Safari on a maintained iOS/iPadOS release.
- Do not add a legacy JavaScript bundle, `@vitejs/plugin-legacy`, or broad compatibility polyfills solely for obsolete browsers.
- Do not freeze the build target to preserve support for aging browser versions as Vite's Baseline target advances.
- Treat operation on older devices and browsers as best-effort: if standards-based output runs correctly, users may use it, but those combinations are not part of the release gate.

This policy targets the modern web platform. A ten-year-old device may still work if it can run a sufficiently current browser, but hardware age alone does not create a support obligation.

## MVP product contract

The MVP provides:

- Start and stop controls.
- BPM entry and tap tempo.
- Meter, subdivisions, and beat accents.
- Click and accent sound with controlled perceptual attacks.
- Volume control.
- Local preference storage.
- Responsive portrait and landscape layouts.
- Mouse, touch, and keyboard operation with accessible native semantics.
- Stable foreground timing driven by the Web Audio clock.
- Recovery messaging and behavior when the audio context is suspended or interrupted.
- A normal HTTPS website plus optional home-screen installation.
- Cached application assets so the metronome can launch and run without an active connection after its first successful load.

The MVP promises dependable foreground playback. Browser and operating-system behavior outside that contract must not be presented as guaranteed.

## Why the web approach fits the MVP

### Reach

- A URL is the common distribution mechanism across modern desktop and mobile devices.
- The Web Audio API is mature and broadly available across current browser families.
- The metronome is computationally small and does not need a remote server while keeping time.
- Static hosting provides the application, while all timing and sound generation remain local to the device.

### Reliability

- Musical events are scheduled on `AudioContext.currentTime`, not generated by UI renders, animation frames, `setInterval()`, network calls, or service workers.
- A short look-ahead queue schedules future beats on the audio clock and protects playback from ordinary main-thread jitter.
- The audio and transport engine is framework-independent TypeScript, allowing the UI to change without rewriting the timing system.

## MVP architecture

```text
Cloudflare Pages HTTPS deployment
  |
  +-- semantic HTML and responsive CSS
  +-- TypeScript UI
  +-- framework-independent metronome engine
  |     +-- AudioContext clock
  |     +-- look-ahead beat scheduler
  |     +-- click synthesis and envelopes
  |     +-- transport, phase, meter, subdivisions, accents
  |     +-- scheduler diagnostics
  |
  +-- local preference storage
  +-- web app manifest and application icons
  +-- service-worker application-shell cache
```

Recommended implementation stack:

- HTML5 and responsive CSS.
- TypeScript compiled by Vite to browser JavaScript.
- Vite's default modern Baseline production target; no legacy bundle.
- Direct Web Audio API for timing and click generation.
- Plain DOM code or a small UI framework; the UI never owns musical timing.
- Native HTML controls and accessible labels before custom widgets.
- Local storage for preferences.
- Cloudflare Pages for static HTTPS hosting.
- No backend or database.

## Timing behavior

- Create or resume the audio context only from an explicit user action.
- Use the audio clock as the single source of truth for transport position and beat phase.
- Use a recurring coarse timer only to refill a rolling look-ahead queue.
- Schedule audio sources and envelope automation ahead of their playback times.
- Render visual beat state separately with `requestAnimationFrame()` while comparing against audio-clock time.
- Define and test how phase behaves during live BPM, meter, and subdivision changes.
- Track scheduler deadlines and late events during development and testing.

## Compatibility boundaries

- Browsers require audio to begin or resume from a user interaction, so the app has an explicit Play control.
- Browsers may throttle or freeze callbacks in background documents; the MVP therefore guarantees foreground rather than indefinite background playback.
- Device output latency is distinct from scheduling accuracy. Stable beat spacing does not imply zero speaker or Bluetooth delay.
- Installation behavior differs by browser and operating system. Failure to offer installation must never block normal browser use.
- If the audio context becomes suspended or interrupted, show a clear recovery state and allow the user to resume.

## Browser test contract

Test on physical hardware rather than relying only on responsive emulation. The release matrix covers current maintained software, not historical device generations:

- Chromium on Windows or macOS and on Android.
- Safari/WebKit on macOS and a physical iPhone or iPad.
- Firefox/Gecko on desktop; Android Firefox is an additional target.
- Built-in speakers, wired output, and Bluetooth output.
- Foreground playback, tab switching, interruption by another application, audio-route changes, sleep/wake, and orientation changes.
- Long sessions plus CPU and UI stress at the minimum and maximum supported BPM.
- Narrow portrait, wide portrait, landscape mobile, tablet, and desktop layouts.
- Keyboard-only and screen-reader navigation of primary controls.

Report these separately:

- Beat-interval accuracy and cumulative drift.
- Missed or late scheduler deadlines.
- First-beat and live-setting-change behavior.
- Device output latency.
- Background survival and interruption recovery.
- Subjective alignment of normal and accented clicks.

## MVP release gate

The release is ready when:

- The production Vite build succeeds reproducibly.
- The audio engine has no dependency on the UI framework.
- Instrumented tests show stable beat intervals and no cumulative drift under expected foreground load.
- Tempo and meter changes follow their documented phase rules.
- Core controls are accessible and usable on narrow and wide layouts.
- The browser/device matrix passes or has documented graceful degradation.
- The public HTTPS URL works as a normal website.
- The PWA can be installed where supported and the cached application shell launches offline.
